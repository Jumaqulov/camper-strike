## YUQORI

### 1. Tarmoq uzilishidan keyin o'yinchi shu hayot davomida butunlay muzlab qoladi
- `src/server/movementAuthority.ts:176-186`
- Wi-Fi ~2 s uzilib, keyin kirishlar paket bo'lib kelsa, navbat (64) to'ladi va `lastQueuedSeq` to'xtaydi.
  Keyingi barcha `seq > lastQueuedSeq + 64` bo'lgani uchun abadiy rad etiladi. Klient redundancy oynasi
  (`newCount + 3`, `Game.ts:1541`) bu oraliqni yopa olmaydi. Faqat qayta tug'ilish (`resetForSpawn`) tuzatadi.
- Belgi: o'yinchi klientda yuradi, har snapshotda orqaga tortiladi ("o'lguncha joyida qotib qolish").
- Tuzatish yo'nalishi: navbat to'lganda yoki oraliq oshganda `lastQueuedSeq` ni yangi seq ga sinxronlash
  (eski kirishlarni tashlab yuborib), yoki klientga ack-stall holatida seq ni qayta boshlash signali.

## O'RTA

### 2. Forest Survival: raund tugaganda g'olib klientda yuradi, serverda muzlagan — rubber-band
- `src/client/game/Game.ts:1724-1746, 1778`; `src/server/room.ts:521-522`; `src/shared/survival/stateMachine.ts:64-79`
- `ended` fazada server kirishlarni rad etadi (`canPlayerMove` false), klient esa `me.alive` bo'lgani uchun
  harakatni bashorat qilib yuboraveradi. Ack kelmagani uchun reconcile har snapshotda server pozitsiyasidan
  120 ta buferni qayta o'ynaydi → ~2 s dan keyin "ko'rinmas devor", W qo'yib yuborilganda orqaga siljish.
  TDM/FFA ta'sirlanmaydi (u yerda `ended` da ham `stepAuthoritativeTick` ishlaydi).
- Tuzatish: klientda `match.phase !== 'playing'` bo'lsa harakatni/`sendInput` ni to'xtatish yoki serverda
  survival `ended` da ham TDM kabi neytral tick qilish.

### 3. Qurol almashtirish + R bir tick ichida: server eski qurolni o'qlaydi → HUD o'q-dori desinxron, "soxta otishlar"
- `src/client/game/Game.ts:2003-2009` (`emit('reload')` qurol id siz va `sendInput()` flush siz), `src/server/room.ts:679-693`
- `reload` darhol, qurol almashtirish kirishi esa keyingi tickda ishlanadi. Klient to'pponchani to'ldirdi,
  server avtomatni o'qlashni boshlab, keyin bekor qildi. Natija: klient to'liq magazin ko'rsatadi, server 0 →
  klientda muzzle flash/ovoz bor, serverda zarar yo'q. `fireLocal` buni to'g'ri qiladi (`sendInput()` avval).
- Tuzatish: `reload` xabariga `weapon` qo'shish va yuborishdan oldin `sendInput()` chaqirish.
